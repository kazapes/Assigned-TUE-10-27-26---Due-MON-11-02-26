## Question 2: How can I check the COBOL program’s return codes?

### AI’s answer in my own words

The program leaves an exit status when it finishes. In this lab, a successful account lookup returns `0`, and a missing account returns `4`. I should run `echo $?` immediately after the command I want to check.

### How I checked it

I ran:

```bash

echo $?
```

The output showed:

```text

NAME=Alice Johnson
STATUS=ACTIVE
BALANCE=5000.00
CURRENCY=USD
```

The return code was `0`.

Next, I ran:

```bash

echo $?
```

The output showed:

```text

ACCOUNT=999999
```

The return code was `4`.

**Result:** Both observed return codes matched the runbook. I captured the commands and results in screenshots.

## Question 3: How does FastAPI communicate with COBOL?

### AI’s answer in my own words

The API receives the account request and calls a Python bridge. The bridge launches the compiled COBOL program, captures its output, and reads its return code. The API uses that information to create the web response.

### How I checked it

I requested the account through the API:

```bash
curl http://127.0.0.1:8000/accounts/100001
```

The response matched the direct COBOL lookup: Alice Johnson, `ACTIVE`, balance `5000.0`, and currency `USD`. It also included `"source":"account_lookup.cob"`. The balance had different formatting but represented the same amount.

I inspected the bridge implementation:

```bash
grep -n -B 8 -A 15 'subprocess.run' app/cobol_bridge.py
```

The code showed that `run_cobol` builds the executable path and uses `subprocess.run()` to launch it. It sets `cwd=BANK_HOME`, captures output, parses `KEY=VALUE` lines, and stores `result.returncode`.

I also inspected the API endpoint:

```bash
grep -n -B 5 -A 15 'def.*account' app/main.py
```

The endpoint called `cobol_bridge.account_lookup(account_id)`.

**Result:** The matching responses and inspected code supported the explanation of how the API communicates with the COBOL core. Matching output alone would have been weaker evidence.
